# Стиль кода ant-ui

Как написан проект. Всё, что можно проверить автоматически, проверяет ESLint (`eslint.config.js`):

```bash
npm run lint       # проверка
npm run lint:fix   # автоисправление того, что исправляется
```

Prettier в проекте не используется — форматирование тоже на ESLint (`@stylistic/eslint-plugin`).
Разделы ниже помечены: **[ESLint]** — проверяется линтером, **[договорённость]** — только этим документом и ревью.

---

## 1. Форматирование [ESLint]

| Что | Как |
|---|---|
| Отступ | 2 пробела, без табов |
| Кавычки | одинарные `'…'`; в JSX-атрибутах — двойные `className="x"` |
| Точка с запятой | обязательна |
| Длина строки | до 120 символов. Длинные строковые литералы (имена файлов в моках, тексты ошибок) не переносим |
| Висячая запятая | в многострочных объектах, массивах, параметрах, импортах — всегда |
| Скобки | стиль 1tbs: `{` на той же строке. Однострочные блоки допустимы: `{ a: 1 }`, `() => {}` |
| Стрелки | параметры всегда в скобках: `(row) => …` |
| Пробелы | внутри фигурных скобок — `{ a, b }`; внутри квадратных и круглых — нет |
| Ключи объектов | в кавычках только когда нужно: `{ ORIGINAL: …, 'aria-label': … }` |
| Пустые строки | не больше одной подряд; файл заканчивается переводом строки |
| Перенос длинных выражений | оператор в начале новой строки: `? :`, `&&`, `\|\|`. Исключение — `=` остаётся в конце строки (`export type Row =` → union на следующих строках) |
| Несколько операторов в строке | не больше двух: `if (!x) return null;`, `for (…) list.sort(…);` |

```ts
// тернарник в одну строку, если помещается
const date = Number.isNaN(parsed.getTime()) ? value : parsed.toLocaleDateString('ru-RU');

// многострочные ветки — в круглых скобках
return row.kind === 'document' ? (
  <FileList files={row.document.versionData.files} />
) : (
  <FolderIcon />
);
```

Поля интерфейса — через `;`; в однострочном типе последний `;` не ставится: `{ document: DocumentData; level: number }`.

## 2. Функции

- **[ESLint] Только стрелочные функции.** `function` не используется ни для компонентов, ни для хуков, ни для утилит:
  ```ts
  export const buildTree = (structure: DocStructureResponse, data: DocumentsDataResponse): TreeRow[] => { … };
  export const useModals = (): ModalManager => { … };
  ```
  Исключения: сокращённые методы объекта (`show(component) { … }` в `createModalManager`) и место, где нужен `this` (с `eslint-disable` и комментарием почему).
- **[ESLint]** Если тело — одно выражение, `{ return … }` не пишется: `const getSnapshot = () => entries;`.
- **[ESLint]** Колбэки — тоже стрелки.
- **[договорённость]** Дженерик у стрелки в `.tsx` — с запятой: `<R = unknown,>() => …`.
- **[договорённость]** Возвращаемый тип указывается у экспортируемых утилит и хуков (`: TreeRow[]`, `: ModalManager`); у компонентов и внутренних колбэков — не указывается.
- **[договорённость]** Внутренние помощники объявляются **выше** места использования (const не поднимается). Исключение — функции, которые вызываются только при рендере (`getColumns` ниже компонента).

## 3. Переменные и выражения [ESLint]

- `const` везде, где нет переприсваивания; `let` — только когда переприсваивается; `var` запрещён.
- Сравнение — только `===` / `!==`.
- Сокращённая запись свойств и методов: `{ counterparty, document }`.
- Склейка строк — шаблонными строками: `` `${companyKey}/${folder.id}` ``.
- Без отрицания в условии, у которого есть ветка «иначе» — сначала позитивный случай:
  ```ts
  // так
  const label = x === null ? '' : x;
  // не так
  const label = x !== null ? x : '';
  ```
  Ранний выход с отрицанием — норма: `if (!modal) return null;`.
- `if` без фигурных скобок допустим, только если тело в той же строке: `if (row.kind !== 'document') return null;`. Многострочное тело — всегда в `{}`.
- `console` в коде библиотеки — предупреждение; в скриптах сборки (`*.mjs`) разрешён.
- **[договорённость]** Для значений по умолчанию — `??`, опциональные вызовы — `?.`: `onCancel?.(e)`, `args[0] ?? {}`.

## 4. TypeScript

- **[ESLint] Типы импортируются с `type`.** Если из модуля берутся только типы — `import type { … }`; если вперемешку — `type` у каждого типа:
  ```ts
  import type { ReactNode } from 'react';
  import { Result, Spin, Table, type TableColumnsType } from 'antd';
  ```
- **[ESLint] Объектные типы — `interface`.** `type` — для union, кортежей, условных и производных типов:
  ```ts
  export interface OrderDocumentsProps { orderId: string }
  export type ValueField = 'signType' | 'assuranceLevel' | 'provisionForm';
  export type TreeRow =
    | { kind: 'company'; … }
    | { kind: 'document'; … };
  ```
- **[ESLint]** `enum` не используется — вместо него union строковых литералов.
- **[ESLint]** Массивы — `T[]`, не `Array<T>`. Словари — `Record<K, V>`, не `{ [key: string]: V }`.
- **[ESLint]** `any` запрещён. Если без него никак — `eslint-disable-next-line` и комментарий почему (пример — `AnyComponent` в `createModalManager`).
- **[ESLint]** Неиспользуемые переменные — ошибка; намеренно неиспользуемый параметр — с `_`: `render: (_, row) => …`.
- **[договорённость]** Размеченные union с полем `kind` для разнородных данных (строки дерева) + `switch (row.kind)`.
- **[договорённость]** `as` — только там, где TypeScript не может вывести тип сам, и рядом комментарий.

## 5. React [ESLint]

- Компоненты — стрелочные функции с деструктуризацией props в параметрах:
  ```tsx
  export const FileLink = ({ file }: { file: DocFile }) => { … };
  ```
  Короткие компоненты — сразу выражением: `export const UiProvider = ({ children }: UiProviderProps) => (<ConfigProvider …>);`.
- Новый JSX-трансформ: `import React` не нужен.
- Фрагменты — `<>…</>`, не `<Fragment>`. Бесполезные фрагменты (вокруг одного элемента) запрещены.
- Компонент без детей — самозакрывающийся: `<FileOutlined />`.
- Boolean-атрибут без `={true}`: `<Flex vertical>`.
- Строковые атрибуты без фигурных скобок: `type="text"`, не `type={'text'}`.
- Ключи списков — по id из данных (`key={file.nkpFileId}`), не по индексу.
- Правила хуков (`rules-of-hooks`, `exhaustive-deps`) — ошибки.
- `propTypes` не используются — типы задаёт TypeScript.
- **[договорённость]** Многострочный JSX — в круглых скобках.
- **[договорённость]** Атрибуты: если не помещаются в строку, каждый на своей строке, закрывающая `>` / `/>` — на отдельной.
- **[договорённость]** Иконки — только из `@ant-design/icons`. Цвета — только из темы antd (`theme.useToken()`), без хардкода `#hex`.
- **[договорённость]** Компоненты antd используются напрямую, без лишних обёрток; своя вёрстка — через `Flex` / `Space`, инлайн-стили — только для мелочей (ширина, отступ).

## 6. Импорты и экспорты

- **[ESLint] Только именованные экспорты.** `export default` — лишь там, где его требует инструмент: сторис (`export default meta`), конфиги Storybook, `*.d.ts`.
- **[договорённость] Порядок импортов:**
  1. `react`;
  2. сторонние пакеты: `antd`, `@ant-design/icons`, `@tanstack/react-query`, `axios`…;
  3. свои модули из других папок через алиас (`@/components/modals`, `@/api/http`);
  4. модули из своей папки (`../common/cells`, `./api`, `./types`).

  Без пустых строк между группами.
- **[договорённость] Алиас `@/` → `src/`.** Импорт за пределы своей области (папки компонента, `src/mocks`, `src/api`) — через `@/`; внутри неё — относительный путь. Глубже одного `../` относительных путей нет.
  ```ts
  import { http } from '@/api/http';
  import { useModals } from '@/components/modals';
  import { saveFile } from '../common/saveFile';
  ```
  Алиас прописан в `tsconfig.json` (`paths`), Storybook — `resolve.alias` в `.storybook/main.ts`, esbuild берёт его из tsconfig сам. В `.d.ts` после `tsc` пути переписывает `tsc-alias` (шаг в `npm run build`), иначе у потребителей пакета типы не найдутся.
- **[договорённость]** Каждая папка компонента экспортирует наружу только через `index.ts` (`export * from './Documents';`). Общий `src/components/index.ts` — список `export *` по алфавиту.
- **[договорённость]** react-query наружу отдаётся только реэкспортом из `ant-ui` — микрофронты не ставят его сами.

## 7. Комментарии [договорённость]

- **На русском.** Тексты в интерфейсе и сообщения об ошибках — тоже на русском.
- Экспортируемые сущности и неочевидные поля — JSDoc `/** … */`, обычно в одну строку:
  ```ts
  /** Файлы документа: первые два в ячейке, остальные — во всплывающем окне по «ещё N». */
  ```
- Внутри кода — `// …` с маленькой буквы, объясняют **почему**, а не что:
  ```ts
  // Flex растягивает элементы на ширину ячейки — иначе многоточие у имён файлов не срабатывает
  ```
- Незавершённое — `// TODO: …` с тем, чего ждём: `// TODO: коды статусов предположительные — сверить с бэкендом`.
- Отключение правила ESLint — всегда с комментарием-причиной на строке выше.

## 9. Структура компонента [договорённость]

Похожие компоненты с разными ручками живут в одной папке: общий UI — в `common/`, у каждого компонента своя подпапка. Режимов через props (`mode: 'view' | 'edit'`) не делаем — каждый компонент сам собирает свои колонки из общих ячеек.

```
src/components/Documents/
  index.ts                      — публичный экспорт: только компоненты (export * from './OrderDocuments')
  common/                       — общий UI, наружу не экспортируется и не знает о ручках
    DocumentsTable.tsx          — Table дерева: загрузка, ошибка, пусто, раскладка колонок
    DocumentModal.tsx           — форма «Документ»
    cells.tsx                   — ячейки: папка, документ, список файлов, значение с иконкой
    hooks.ts                    — общие хуки (состояние скачивания)
    saveFile.ts                 — отдать Blob браузеру как файл
    types.ts                    — простые типы для общих ячеек (FileInfo)
  OrderDocuments/               — документы заявки (просмотр)
    OrderDocuments.tsx          — компонент: запросы → строки → DocumentsTable
    OrderDocuments.stories.tsx  — сторис (все состояния: данные, пусто, загрузка, ошибки)
    index.ts
    api.ts                      — функции запросов (axios)
    hooks.ts                    — хуки react-query и префикс ключей
    types.ts                    — типы ответов бэкенда (как в описании API)
    buildTree.ts                — сборка дерева из ответов, чистая логика без React
    columns.tsx                 — колонки; ответ бэкенда → props общих ячеек
    fields.tsx                  — настройки полей: подписи, иконки, ширины
    docs/                       — требования, описание API, скриншоты, макеты
  TaskDocuments/                — документы задачи (редактирование), устроен так же
```

- `common/` не импортирует ничего из подпапок компонентов. Ячейки принимают простые props (`name`, `version`, `FileInfo`), а не ответ бэкенда: каждый компонент приводит к ним свои данные в `columns.tsx`.
- Если код нужен только одному компоненту — он в его подпапке. В `common/` переносим, когда он реально понадобился второму.
- Логика отдельно от вёрстки: преобразование данных — чистые функции в `.ts`.
- Запросы — только через функции из `api.ts` и только через `http` из `src/api/http.ts` — общий экземпляр axios для всех компонентов, добавляет `Authorization: Bearer <JWT из localStorage>` (не глобальный axios), ошибки HTTP бросает axios.
- Ключи react-query начинаются с константы компонента (`[ORDER_DOCUMENTS_KEY, 'documents', …]`), чтобы инвалидировать всё дерево одним вызовом.

## 10. Моки и сторис [договорённость]

- Данные — `src/mocks/data/*.ts`, хендлеры MSW — `src/mocks/handlers/*.ts`.
- Хендлеры сценариев — объектом `xxxHandlers` (`documents`, `documentsError`, `documentsLoading`…); общие успешные — в `defaultHandlers`, подключаются в `.storybook/preview.tsx`.
- В историях сценарий включается через `msw.use(...)` в `beforeEach`.
- Моки повторяют реальные ответы бэкенда; отличия от реального ответа — комментарием над данными.

## 11. Зависимости [договорённость]

- Версии в `package.json` — точные, без `^` / `~` (`npm install --save-exact`). Исключение — `peerDependencies`.
- `react` и `react-dom` — только `peerDependencies` (+ devDependencies для разработки).

## 12. ESLint и TypeScript 7

Проект собирается TypeScript 7, у которого нет JavaScript API, а `typescript-eslint` без него не работает.
Поэтому линтеру отдельно поставлен TypeScript 5.9 под именем `typescript-eslint-ts`, а `eslint.typescript.cjs`
подменяет им `require('typescript')` внутри пакетов `@typescript-eslint/*`. `overrides` в `package.json` нужны,
чтобы npm принял TS 7 как peer-зависимость `typescript-eslint` (официально — до 6.1).

Когда `typescript-eslint` начнёт поддерживать TypeScript 7 — убрать `eslint.typescript.cjs`, его импорт из
`eslint.config.js`, пакет `typescript-eslint-ts` и `overrides`.
