# OrderDocuments (документы заявки) — поведение

Данные, сборка дерева и колонки: [backend-api.md](backend-api.md). Макет: [mockups/scheme.png](mockups/scheme.png).

## Отображение

- Tree-table на базе antd `Table`.
- При загрузке дерево **раскрыто полностью**. Строки, появившиеся после перезапроса данных, тоже раскрыты; свёрнутые пользователем остаются свёрнутыми.
- Пустые папки и типы документов скрыты.
- Иконки (`@ant-design/icons`): папка и тип документа — `FolderFilled` с жёлтой заливкой (`colorWarning` из темы), документ — `FileTextOutlined` в основном цвете темы (`colorPrimary`, как у ссылок), файл — `PaperClipOutlined`.
- Строка документа всегда в одну строку: длинное название обрезается многоточием, полное — в тултипе. Версия остаётся видна. Так строка не «прыгает» к левому краю при сужении окна.
- Компании выделены жирным. Строки компаний, папок и типов документов растянуты на всю ширину.
- Статус — цветная метка (`Tag`) по `statusCode`, коды из справочника `doc_status`:

  | `statusCode` | Название | Описание | Цвет |
  |---|---|---|---|
  | `NewDoc` | Новый | Документ добавлен в НКрК | синий |
  | `InProgress` | В работе | Документ находится в работе у сотрудника | жёлтый |
  | `InApprove` | Согласование | Документ отправлен на согласование | фиолетовый |
  | `Actual` | Актуальный | Документ актуален, имеет актуальные данные, все согласования и подписания | зелёный |
  | `Archive` | Неактуальный | Документ неактуален | серый |

  Неизвестный код — серая метка.

### Значения полей

Вид заверения, форма предоставления и способ подписания приходят кодами. Подпись — `value` из справочника
`GET /credit-doc/docTypeDict/{docType}` (см. [backend-api.md](backend-api.md#3-справочник-типа-документа)), иконка — по коду
из `FIELD_ICONS` (`common/fields.tsx`), общие для обеих таблиц.

| Поле | Код | Иконка |
|---|---|---|
| Вид заверения | `ORIGINAL` | `FileProtectOutlined` |
| | `COPY_NOTARY` | `AuditOutlined` |
| | `COPY_AUTHOR` | `CopyOutlined` |
| | `COPY_CLEAN` | `SnippetsOutlined` |
| | по умолчанию | `FileOutlined` |
| Форма предоставления | `ORIGINAL` | `FileProtectOutlined` |
| | `PAPER` (TODO) | `PrinterOutlined` |
| | `ELECTRONIC` (TODO) | `CloudOutlined` |
| | по умолчанию | `InboxOutlined` |
| Способ подписания | `EMBEDDED` (TODO) | `SafetyCertificateOutlined` |
| | `DETACHED` (TODO) | `DisconnectOutlined` |
| | `ABSENT` (TODO) | `StopOutlined` |
| | по умолчанию | `EditOutlined` |

Коды с пометкой TODO придуманы: в ответе бэкенда их нет или они пустые.
Код, которого нет в справочнике (или справочник не загрузился), выводится как есть, с иконкой по умолчанию.
- Выбора строк нет. Hover — стандартный для antd `Table`.

## Документ

- Название документа (`docName`) выглядит как ссылка.
- Клик открывает форму «Документ» в режиме только для чтения (п. 9.3 ТЗ). Пока это пустая модалка-заглушка.

## Файлы

- Список внутри строки документа. Под именем файла серым — дата загрузки и автор.
- В ячейке показываются первые 2 файла, остальные — во всплывающем окне по ссылке «ещё N» (ширина окна до 400px).
- Длинное имя обрезается многоточием, полное — в тултипе.
- Нет файлов — серая надпись «Нет файлов».
- Имя файла выглядит как ссылка. Клик → `GET /credit-doc/elar-file/{fileId}`, в параметр передаётся `files[].nkpFileId`. Результат отдаётся пользователю как файл. Ошибка — уведомление с именем файла и текстом ошибки, ссылка подсвечена красным.
