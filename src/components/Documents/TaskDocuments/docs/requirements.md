# TaskDocuments — поведение

Отображение дерева, документа и файлов — как в [OrderDocuments](../../OrderDocuments/docs/requirements.md).

## Статус

`versionData.statusName` — цветная метка (`Tag`) по `versionData.statusCode`. Коды — из справочника `doc_status`:

| `statusCode` | Название | Описание | Цвет |
|---|---|---|---|
| `NewDoc` | Новый | Документ добавлен в НКрК | синий |
| `InProgress` | В работе | Документ находится в работе у сотрудника | жёлтый |
| `InApprove` | Согласование | Документ отправлен на согласование | фиолетовый |
| `Actual` | Актуальный | Документ актуален, имеет актуальные данные, все согласования и подписания | зелёный |
| `Archive` | Неактуальный | Документ неактуален | серый |

Неизвестный код — серая метка.

## Редактируемые поля

- «Вид заверения», «Форма предоставления», «Способ подписания» — выбор из списка (`Select`), каждое в своей колонке.
- Редактируются только строки документов. Документ, пришедший в ответе `/taskList`, считается созданным.
- Права не проверяются: если пользователь видит компонент, он может редактировать.
- Варианты списка — `{поле}.List` из `GET /credit-doc/docTypeDict/{docType}`, свои для каждого типа документа. Подпись — `value`, иконка — как в OrderDocuments (`common/fields.tsx`). Очистить значение нельзя.
- Текущий код, которого нет в справочнике, выводится как есть, с иконкой по умолчанию.
- Пока справочник грузится — индикатор загрузки в селекте. Ошибка загрузки — селект подсвечен красным, в тултипе текст ошибки.

## Сохранение

- Сразу при выборе значения, без кнопки «Сохранить».
- Пока идёт сохранение и перезапрос `/taskList`, селект заблокирован и показывает загрузку.
- Ошибка — уведомление с названием документа и текстом ошибки, селект подсвечен красным, в тултипе текст ошибки, значение остаётся прежним. Подсветка снимается при следующем успешном сохранении этого поля.

## Добавление документа

- Кнопка-иконка `FileAddOutlined` с тултипом «Добавить документ» сразу после названия вида документа, перед кнопкой исключения.
- Кнопка добавления синяя, кнопка исключения красная.
- Клик открывает форму «Документ» (п. 9.3 ТЗ) в режиме создания. Пока это заглушка: модалка «Новый документ» с переданными параметрами.
- Параметры: `docTypeId` — код вида из `/doc-structure`, `docInEntityId`, `counterpartyName`, `counterparty`, `counterpartyCode` — из контрагента строки.

## Добавление документа к компании

- Кнопка-иконка `FileAddOutlined` с тултипом «Добавить документ» сразу после названия компании. Кнопка у вида документа — пока заглушка (см. выше).
- Клик открывает модалку «Добавить документ»:
  - «Контрагент» — `counterpartyName` строки компании, текстом;
  - «Вид документа *» — селект из `GET /credit-doc/docTypesDict?archive=false`. В отличие от ТЗ («запрос при открытии
    ВК») список запрашивается при первом открытии и дальше берётся из кэша (`staleTime: Infinity`). Если модалку
    не открывали дольше 5 минут (`gcTime` по умолчанию), кэш сбрасывается и список запрашивается заново.
    Подпись — `codeEkd · shortName`, поиск по `codeEkd`, `shortName`, `fullName`. Пока список грузится — индикатор
    загрузки. Ошибка — уведомление «Не удалось загрузить виды документов» с текстом ошибки, селект подсвечен
    красным, под ним текст ошибки и ссылка «Повторить» (перезапрос), в раскрытом списке тот же текст вместо
    «Нет данных». Повтор с ошибкой показывает уведомление снова, не дублируя его;
  - «Файлы *» — кнопка «Выбрать файлы» (можно несколько). Под ней — карточки файлов, при превышении 280px
    вертикальная прокрутка. В карточке: иконка по расширению (pdf, Word, Excel, изображение, архив, прочее), имя
    (обрезается, полное — в тултипе), размер и статус («Загружается…», «Загружен», «Ошибка: …»), справа — удаление,
    спиннер или галочка. Карточка с ошибкой подсвечена красным. Пусто — `Empty` «Файлы не выбраны».
    Файлы на бэкенд сразу не отправляются.
- «Добавить» недоступна, пока не выбран вид и нет хотя бы одного незагруженного файла. Пока идут запросы, «Добавить»
  показывает загрузку, выбор файлов и удаление заблокированы.
- «Добавить» → `POST /new-document-to-list`, затем `POST /file/{docVersionId}` на каждый файл, параллельно.
- Все файлы загружены — уведомление «Документ добавлен» с названием вида, модалка закрывается, перезапрашивается `/taskList`.
- Часть файлов не загрузилась — уведомление «Не все файлы загружены» (сколько из скольких), модалка остаётся открытой,
  у упавших файлов красная иконка и текст ошибки в тултипе. Документ уже создан: вид документа блокируется, загруженные
  файлы удалить нельзя. Повторное «Добавить» отправляет только незагруженные файлы в ту же версию. `/taskList`
  перезапрашивается и в этом случае.
- Ошибка `new-document-to-list` — модалка остаётся открытой, уведомления нет. Между файлами и кнопками — `Alert` «Не удалось добавить документ»: `message` из ответа бэкенда
  (если нет — текст ошибки axios) и «Код ошибки: {HTTP-статус}». Повторное «Добавить» скрывает его и снова создаёт
  документ.
- «Отмена» и крестик закрывают модалку без предупреждений.
- `multipleInList` и `client` не используются, шаги 3–4 ТЗ не делаются. Ограничений на количество, размер и тип файлов нет.

## Исключение вида документа

- Кнопка с корзиной после кнопки добавления документа.
- «Конфигурация опционального отображения» из ТЗ не делается: просмотр без удаления — это OrderDocuments, с удалением — TaskDocuments.
- Клик открывает модалку шириной 420px: красная иконка-предупреждение и заголовок «Вы уверены, что хотите исключить
  вид документа из списка?», под ним строка ««{вид}» и его документы (N) будут исключены из списка компании
  {компания}.» (без документов — ««{вид}» будет исключён из списка компании {компания}.»). Кнопки «Отмена» /
  «Да, исключить» (красная; в ТЗ — «Да»).
- «Да, исключить» → `DELETE /credit-doc/document-in-entity/{docInEntityId}`, пока запрос идёт, кнопка показывает загрузку.
- Успех — уведомление с названием вида, модалка закрывается, перезапрашивается `/taskList`. Ошибка — модалка остаётся
  открытой, уведомления нет, над кнопками `Alert` «Не удалось исключить вид
  документа» с текстом из ответа бэкенда и кодом ошибки.
